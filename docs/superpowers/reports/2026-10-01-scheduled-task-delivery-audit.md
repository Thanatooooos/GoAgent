# 通用定时任务首轮交付审计

日期：2026-10-01。结论：**partially aligned**。通用任务主入口已接入，真实模型、HTTP、浏览器和后台投递均有证据；体育试点关口及 DailyBrief 统一任务关口尚不能宣布通过。

## 承诺范围与真实入口

按 2026-09-30 规格和实施计划执行，没有另起设计。聊天提议及管理页是用户入口；`cmd/server/main.go` 创建并启动通用任务 worker，受保护的 `/api/ragent/scheduled-tasks` API 使用同一任务仓储。到点执行调用 `internal/app/runtime.RunTask`，不预先启动独立采集器。自动执行只写任务、运行记录、应用内会话及未读。

DailyBrief 的 `internal/bootstrap/dailybrief/runtime.go` 仍使用原独立 schedule loop 及 `SourceCollector -> CandidatePipeline -> RuntimeBriefGenerator`。未建立订阅映射、artifact 投影及新旧发布所有者切换，因此阶段 8 全部保持未勾选。原 issue 页面与旧调度仍保留。

## 真实调用观察

模型服务使用用户提供的 `.env` 硅基流动配置；未将密钥写入报告。提议模型为 `Qwen/Qwen3-32B`，运行模型为 `deepseek-ai/DeepSeek-V4-Flash`。所有写入均发生在专用临时数据库 `codex_scheduled_20261001_round3`。

| 样本 | 计划与结果 | 可观察事实 |
| --- | --- | --- |
| 提醒任务 39609695937294593 / occurrence 39609901944729857 | 上海 14:08:48，约 14:09:01 被扫描执行，14:09:03 发布 report | 确认时未建专用会话；关闭浏览器后后台创建会话 39609904863965441，消息 39609904864030977；一次运行、一次发布 |
| FIFA 当前网页状态任务 39611208822747393，版本 2 / occurrence 39612379318776065 | 上海 14:33:27 计划，report，消息 39612398176432385 | web_fetch 确实成功获取 fifa.com HTML；最终 JSON 与消息来源一致。它只证明网页可访问，不能证明比赛公告内容已读全 |
| FIFA 延期事件任务 39609912145277185，版本 3 / occurrence 39613292938850561 | 确认基线 14:42:07，计划 14:42:34，约 14:43:21 返回 no_report | 4 次 web_search、2 次 web_fetch 均完成，结果范围为 fifa.com 及其子域；没有发布消息，没有懒建会话。未用覆盖规则阻断，也没有将 no_report 称为已查全 |
| 早期事件版本 1 | 同一 occurrence 的 3 次尝试因自由文本/JSON 混杂失败 | 严格解析拒绝发布，保存失败与工具记录并按有效窗口重试；这不是 3 次计划运行，不能触发“连续 3 次计划失败”通知 |
| 早期 JSON 模式事件/状态尝试 | 合法 uncertain；个别 no_report 无工具 | 对照调用发现 provider 的 JSON 模式会压制工具调用，甚至声称已获取网页。已修复工具阶段使用普通模式、最终格式阶段才启用 JSON；保留旧样本供离线复盘，没有增设在线完成判定 |

离线判读：当前状态报告与保存的实际 HTML 获取相符；事件 no_report 的检索未找到可确认晚于基线的新延期公告，但这些网页结果不足以证明公告不存在，因此漏报标签为**未判定**。不确定样本没有发布；早期未调用工具却描述检查失败的输出属模型证据风险。样本横跨提示词及传输修复，不能混成一个稳定版本的成功率。尚不提供误报率、漏报率或“试点可靠”的结论。

本轮定位并修正：提议嵌套字段与错误意图识别、首条聊天建会话时丢失提议、API null 数组、journal TEXT evidence 的 JSON 读取、report 来源未写消息、一次提醒未完成、失败通知及扫表饥饿、JSON 模式压制工具、失败返回丢失 runtime session、旧版本结论状态、编辑后低频反馈基线。

补测中，相似的既有暂停任务让模型把“现在整理消息”和缺少频率的“有新公告就告诉我”误判为 resume。提议规则现明确：既有任务仅为参考，匹配主题或暂停状态不是恢复意图；立即执行请求为 none，缺少频率的监测仍须 clarify。打开任务汇报会话还发现旧 currentSessionId 与新路由竞态；ChatPage 现尊重显式会话路由，读取历史配置与提醒正文的浏览器复测通过。

修正后的真实提议评估 9/9 符合预期：未来事实提问 none、查看任务 manage/open_manager、立即整理 none、缺少频率 clarify、指定日期提醒 draft、每周总结 draft、每日条件监测 draft、显式暂停 manage/pause、指定任务改频率 draft。该小样本不代表所有自然语言表达的召回率；原始评估前后结果分别保存在 `tmp/scheduled-task-proposal-language-before-fix.json` 和 `tmp/scheduled-task-proposal-language-e2e.json`，提议测试均未确认草稿。

- `go test ./cmd/... ./internal/... -run '^$'` 编译检查通过；不是全仓库全量功能测试。
- 专用库 `codex_scheduled_20261001_round5` 的生命周期、失败通知/恢复、低频反馈、并发认领与发布恢复测试通过；同一库 `-count=2` 通过。断言只核对当前任务的会话，不清空历史未读来求通过。
- npm build 脚本通过（3615 个模块）。系统 npm.cmd 固定 Node 20，与 npm 12 不兼容；本轮用已安装的 Node 24 执行 npm-cli.js 的 `run build`，未安装或升级依赖。
- 全量 TypeScript 检查仍有其他既存脏文件的诊断；本轮定时任务相关四个前端文件没有匹配诊断。不能称全量类型检查通过。

## 默认配置与复测

`configs/application.yaml` 已装配并验证正值：扫描 15 秒、每批 20、并发 4、租约 900 秒、一次结果窗口 600 秒、周期结果窗口 1800 秒、最多 3 次尝试、重试间隔 60 秒、日/周/月监测反馈间隔 7/30/60 天、连续失败或不确定通知阈值 3 次计划运行。反馈计数按 occurrence，不按重试 attempt。间隔不超过一天的监测使用日反馈默认，否则使用周反馈默认。

夏令时缺失时刻取当天第一个不早于请求的有效本地分钟；重复时刻取第一次，只触发一次；月末不存在的日期跳过。任务草稿有效期当前固定 24 小时。计划要求的运行记录保留期及独立可配置调度抖动仍未落地，阶段 0 的默认值整条不能勾选。

复测需要 Docker 数据库/依赖服务及可用模型凭据。Go 命令设置 `GOCACHE=D:\goagent\tmp\codex-gocache`；数据库集成测试设置 `SCHEDULED_TASK_TEST_DSN` 指向专用临时库。前端 `VITE_API_BASE_URL` 指向 `/api/ragent`。不要把真实模型验证改成拦截请求或伪造工具结果来计算试点通过。
