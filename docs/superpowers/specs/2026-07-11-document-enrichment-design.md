# 文档父子切块与 LLM 增强设计

## 目标与范围

为现有 `chunker -> enricher -> indexer` 入库流水线增加三项能力：

- 父子切块：小子块用于检索，大父块用于回答上下文。
- 问题预测：LLM 为每个子块生成可被其充分回答的问题，并作为独立检索入口。
- 文档摘要：LLM 基于文档采样内容生成一份可展示、可用于检索增强的摘要。

一期只支持现有的固定长度和 Markdown 切块策略，不包含自适应三层切块、上传批次配置覆盖和前端切块预览。

## 现状

当前 `ChunkerNodeRunner` 产出扁平 `ChunkPayload`，`IndexerNodeRunner` 将每个 chunk 同时写入 `t_knowledge_chunk` 和 `t_knowledge_chunk_vector`。增强节点当前只能产生启发式关键词和问题元数据，问题不会进入向量索引。检索命中一个 chunk 后，无法展开更大的原文上下文。

## 方案选择

采用在既有流水线内增强的方案：

1. `chunker` 生成父块、子块及其关联。
2. `enricher` 调用 LLM 生成文档摘要和每个子块的预测问题。
3. `indexer` 原子地写入父块、子块、摘要和问题索引；正文向量只对应子块，问题向量通过 `source_chunk_id` 回链子块。
4. 检索合并正文命中与问题命中，按原子子块去重，再按父块展开上下文。

不采用“问题/摘要直接拼接进正文向量”的方案，因为其无法识别命中来源、难以去重，并会污染正文语义。

## 数据模型

扩展知识块的持久化模型，区分下列记录：

- `parent`：父块，保存全文上下文，不生成正文向量。
- `child`：子块，保存可精确引用的正文，生成正文向量；带 `parent_chunk_id`。
- `question`：预测问题，保存问题文本和 `source_chunk_id`，只生成问题向量。

文档表增加 `summary`、`summary_status` 和可选的 `summary_error_message`。摘要不是检索正文的一部分，不会替代正文证据。

问题向量可与正文向量共用 `t_knowledge_chunk_vector`，通过 metadata 中的 `record_type=question`、`source_chunk_id`、`parent_chunk_id` 区分；其 `chunk_id` 必须唯一且可由文档、源子块和问题序号稳定生成。这样不需要新增第二个向量检索通道。

## 流水线与配置

`chunker` 新增可选设置：

- `enableParentChild`：默认关闭，保障已有流水线行为不变。
- `parentChunkSize`、`childChunkSize`、`childOverlapSize`：父/子块大小与子块重叠。

父子切块算法先按父块大小使用现有策略切分，再在每个父块内按子块大小切分；子块索引在文档内全局递增，保留父块引用。

`enricher` 新增 LLM 模式与设置：

- `summary`：生成一份文档摘要；输入是受最大字符数限制的均匀采样内容。
- `questions`：按子块生成预测问题；每个子块默认至多两个问题。
- `modelId`、`questionCount`、`maxQuestionLength`、`summaryMaxInputChars`：成本与输出上限。

生成提示词要求问题只覆盖该子块能够完整或主要回答的真实检索意图，禁止依赖“这篇文章/该段”等指代；摘要必须只依据输入内容生成。输出须做去空、去重、长度校验。

## 写入与重试

`indexer` 的写入顺序如下：

1. 基于文档 ID 清理旧父块、子块、问题向量和摘要状态。
2. 批量持久化父块与子块。
3. 嵌入并写入子块正文向量与问题向量。
4. 持久化文档摘要及生成状态。

任一步出现索引写入错误时，执行现有的按文档补偿删除逻辑，删除所有新增块和向量，允许队列完整重试。LLM 摘要或问题生成错误不视为索引失败：记录对应状态和日志后，继续写正文子块向量，保证文档仍然可检索。

## 检索回链

检索层读取正文和问题向量：

1. 正文命中以自身 `chunk_id` 作为原子子块 ID。
2. 问题命中从 metadata 的 `source_chunk_id` 解析原子子块 ID。
3. 按原子子块 ID 去重，保留最高分与命中来源。
4. 若存在 `parent_chunk_id`，批量加载父块内容作为回答上下文；否则返回子块正文以兼容旧数据。

返回结果仍携带原子子块 ID 作为证据引用 ID，避免父块展开破坏引用精度；同时在 metadata 标记 `retrieval_source` 为 `content` 或 `question`，用于调试和 Trace。

## 兼容性与安全

- 旧数据没有 `record_type` 或父块引用时，按普通正文子块处理。
- 关闭父子切块、LLM 增强或 LLM 不可用时，退回当前扁平正文切块与索引行为。
- 生成内容不记录用户密钥、请求头或完整模型提示词；错误文本按既有日志长度规则截断。
- 新配置的默认值必须保持现有索引数量与查询语义不变，避免升级后无感增加模型成本。

## 验证

单元测试覆盖：

- 父子切块的稳定索引、父引用、边界和关闭时的兼容输出。
- 问题与摘要的输出清洗、去重、LLM 失败降级。
- 索引写入的父/子/问题关联、稳定 ID 和补偿清理。
- 问题命中回链、正文与问题命中去重、父块上下文展开和旧数据回退。

集成测试覆盖一条真实流水线：解析文档、父子切块、模拟 LLM 增强、写入索引并以预测问题检索，断言最终返回父块上下文与原子子块证据。
