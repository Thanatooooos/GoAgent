# 图片证据入库与视觉描述规格说明书

日期：2026-09-24  
状态：已确认目标语义，待实现

## 背景与目标

当前统一入库入口是 `DocumentProcessService.ExecuteChunk`。DocReader 为 PDF、Office、EPUB 和独立图片提供正文与图片帧；图片帧现经 Tesseract OCR 后合并为文本。解析结果只有 `Text` 与 `Metadata`，`extractDocumentText` 只向分块流程返回文本。引用以 chunk ID 定位，聊天引用弹层只展示 chunk 内容。现有 OCR 无法表达图表、流程图和照片中的非文字信息。

本规格要让文件内的图片成为可检索、可引用、可在聊天中查看原图的独立证据，同时保留 OCR 的逐字结果。图片处理允许部分失败，并在恢复、重分块和文档删除时维持可解释的状态与引用。

## 范围

- 第一版处理 DocReader 能从文件中提取的内嵌图片，以及独立上传的图片文件。每次图片出现都是独立证据单元；同一图片在文件中出现两次，应有两个出现 ID。
- 每张图片默认同时执行 OCR 与视觉描述。`no_text` 不能作为跳过视觉描述的条件。OCR 与视觉描述各自记录状态、内容及错误。
- Markdown/HTML 中指向外部地址的图片第一版不下载。检测到未处理的外部图片引用时，明确展示原因；若已有可检索内容，文档最终为 `partial`。不得把链接文字当成已经理解的图片内容。
- 第一版不提供人工修正图片 OCR 或描述的界面和接口。图片证据直接参与检索；AI 图片描述不进入现有文档摘要、chunk 摘要和预测问题生成。现有 OCR 文字参与文档摘要的能力须保留，普通正文沿用现有增强流程。
- 不改造聊天模型为多模态回答。回答模型接收图片证据的标明来源的文字；用户通过确定性的引用弹层查看原图。

## 术语与证据契约

| 术语 | 含义 |
| --- | --- |
| 图片出现（occurrence） | 图片在某个文档版本中的一次出现，由文档版本 ID 与出现序号定位；DocReader `original_ref` 仅作解析定位，不能单独作为持久 ID。 |
| 图片证据 | 一次图片出现的 OCR 文字、视觉描述、相邻正文、处理状态和原图引用。它独立建索引，引用只对应这一张图。 |
| 证据版本 | 某次发布的不可变图片证据快照。新 OCR/描述结果产生新版本；旧聊天引用保留旧版本 ID。 |
| 原图 | 从文件提取并受权限保护保存的图片字节。可另制作用于 OCR、视觉模型和缩略图的处理副本。 |
| 生成内容 | 视觉模型给出的描述；必须与文件原文、OCR 逐字结果和相邻正文分别标记。 |

视觉描述只能陈述图片中可辨认的对象、文字、结构和关系。相邻正文可帮助识别主题，但不能把正文中的数值或结论写成“图中可见”；无法辨认的内容要明确表示不确定。OCR 输出不能被描述改写成逐字引文。图片证据进入回答上下文时，应带上来源标记；引用弹层分别展示原图、OCR、AI 描述和相邻正文。

## 模型与请求

视觉描述使用硅基流动平台模型 **`Qwen/Qwen3.8-27B`**。该精确 ID 已出现在[硅基流动模型中心](https://www.siliconflow.cn/models)，页面将其列为支持视觉输入的模型。按[官方视觉接口说明](https://docs.siliconflow.cn/docs/userguide/capabilities/vision)，使用 `/v1/chat/completions` 的多模态 `messages[].content`，包含 `image_url` 图片项和 `text` 提示项；图片可用带 MIME 的 base64 data URL 发送，避免为模型调用暴露对象存储公网地址。实际账号对该模型和图片输入的可用性须在联调时验证。

请求形状如下；`image_url.url` 使用经过尺寸约束的处理副本，示例中的 base64 仅为占位符：

```json
{"model":"Qwen/Qwen3.8-27B","stream":false,"messages":[{"role":"user","content":[{"type":"image_url","image_url":{"url":"data:image/png;base64,<encoded-image>","detail":"high"}},{"type":"text","text":"仅描述图片中可见的信息；不要从相邻正文补充看不清的数值。"}]}]}
```

模型输出应要求包含可见描述与不确定项；适配器负责校验并归一化，不假设模型总能按提示返回有效结构。具体图片像素和输出 token 上限在实现时通过样本联调确定，并作为配置固定。

视觉模型使用独立配置：平台地址、模型 ID、密钥引用、单图超时、并发数、处理副本尺寸及输出长度。模型白名单只包含明确配置的目标模型；请求失败不能自动回退到未指定的外部提供商。密钥不得进入日志、证据元数据或聊天内容。记录模型 ID、请求时间、结果状态和可获得的用量，便于诊断与成本核算。原图允许发送至明确配置的硅基流动平台。

视觉模型返回后由适配器归一为 `described`（有可核对的描述）、`no_content`（正常处理但没有值得索引的可见内容）或 `error`（调用、超时、响应解析等失败）。不能仅凭模型输出了非空字符串就认定 `described`；空白、模板套话和无法解析的结果需按约定校验。`no_content` 不属于失败，也不生成无意义的检索文本。

## 解析与处理流程

1. DocReader 解析文件，输出正文和带出现序号、`original_ref`、MIME、图片字节的图片清单。解析层不再只返回一段扁平文本；图片占位位置和可获得的页码等定位信息一起传给处理服务。没有可靠页码时只显示“第 N 张图片”，不得推测页码。
2. 在发布当前文档版本前，为每次图片出现保存原图副本及任务记录。所有可提取图片都要登记，包括暂时无法处理或超过单批容量的图片。图片任务采用持久化记录与租约，服务重启后可恢复。
3. 正文按现有父子分块流程发布。OCR 逐图处理；已完成的 OCR 文字可先检索。视觉描述随后异步补齐，不阻塞正文和已完成 OCR 的检索。OCR 与视觉描述使用独立任务和结果字段，必要时并发执行，但不得让一项结果覆盖另一项。
4. 每次图片出现形成一个独立的可引用证据单元。其检索文本由 OCR 文字、视觉描述和少量相邻正文构成，须标明各自来源并清除明显重复；原图字节不进入向量。OCR 文字仍可进入文档摘要的输入，但不应因此在普通正文与图片证据中重复建立同一份 OCR 向量。图片证据不按普通字符长度拆成多个可混淆的引用单元。若内容超过嵌入上限，应压缩检索表示，同时保存完整证据供引用展示。
5. 图片证据发布或更新时，为新版本生成嵌入并原子切换活动索引指针。已发布版本保持不可变。普通正文和图片证据可以逐阶段可见，但检索结果必须带文档版本 ID 与证据版本 ID，不得混入其他文档版本的图片。
6. 所有图片处理结束或重试耗尽后，根据下节规则收口文档状态。文件重分块和远程刷新以新的文档版本构建索引；上一已发布版本在新版本可用前继续检索。旧任务结果只允许写入匹配的文档版本与图片出现记录。

## 单图与文档状态

| 处理项 | 有内容 | 正常无内容 | 错误 |
| --- | --- | --- | --- |
| OCR | `success`，保留逐字结果 | `no_text` | `error`，保留原因与重试信息 |
| 视觉描述 | `described`，保留生成描述 | `no_content` | `error`，保留原因与重试信息 |

`no_text` 与 `no_content` 不计入失败，也不自动互相推导。OCR 成功、描述失败时，OCR 仍可检索；描述成功、OCR 失败时，描述仍可检索，但不得将其呈现为逐字识别结果。

| 文档状态 | 判定与可见性 |
| --- | --- |
| `running` | 当前版本仍在处理。已发布的正文、OCR 和图片证据可检索；若是重试，上一已发布版本继续可用。界面显示待处理图片数。 |
| `success` | DocReader 已确认图片清单，所有必处理项目正常结束（包括 `no_text` / `no_content`），且至少有一条可检索内容。不存在未处理的外部图片引用。 |
| `partial` | 至少有一条可检索内容，但单图 OCR/描述失败或图片清单因 Tika 回退未确认，或存在第一版不处理的外部链接图片。界面显示失败/未处理项目和原因。 |
| `failed` | 处理结束后没有任何可检索内容，或解析错误导致无法安全建立正文与图片关系且没有可发布结果。保留诊断信息供重试。 |

新增 `partial` 时必须更新文档状态流转、分块日志、查询过滤、删除条件、重新分块入口、远程刷新与前端状态展示。`partial` 不等同于“仍在处理”。历史的摘要 `degraded` 状态与图片处理状态分别保存，不混用。

## 回退、容量与失败恢复

- DocReader 不可用或结构解析失败时，可沿用 Tika 回退来取得纯文本；若文本可检索，状态为 `partial`，原因是 `image_inventory_unknown`，并安排 DocReader 重试。Tika 不提供图片清单，不能据此宣称无图片或标记完整成功。无可检索文本时为 `failed`。
- 当前“超过 100 张图片即整份解析失败”和单图 10 MiB 限制需要改为分批及单图处理规则。图片均应登记；超过单批容量的图片保持待处理。超大图片可制作有尺寸与格式约束的处理副本，原图用于展示。无法制作副本时记录该图片的错误，按文档状态规则收口，不静默跳过。
- 对超时、限流和临时服务错误进行有限次数自动重试，采用退避间隔；`no_text` 与 `no_content` 不重试。达到上限后保留 `partial`，在文档详情列出失败项，并提供手动重试失败项的入口。成功项可按图片内容哈希、模型 ID、提示词版本与处理参数复用，但出现 ID 与证据引用仍独立。
- 重试只替换准备好的新活动证据，不能清空已有可检索内容。重试再次失败时，恢复上一发布状态和失败原因。任务结果写入须检查文档未删除、文档版本与图片出现 ID 匹配；迟到结果丢弃并清理其临时副本。
- OCR 或描述返回错误与嵌入/持久化错误区分。图片处理错误可导致 `partial`；索引写入失败不能宣称新证据已发布。失败原因按图片、处理项、阶段记录，日志不保存原图和密钥。

## 持久化与引用

建议新增以下概念性记录，具体表名由实施设计确定：

- `document_revision`：不可变版本 ID、源文件标识、当前/历史发布状态与时间。文档保留活动版本指针。
- `image_occurrence`：文档版本、出现序号、DocReader 引用、可用位置、原图对象键、MIME、内容哈希，以及 OCR/描述的独立状态与任务信息。
- `image_evidence_version`：不可变证据版本 ID、图片出现 ID、OCR 原文、AI 描述、相邻正文、模型与提示词版本、发布时间。只有活动证据版本进入向量检索；历史版本只供旧引用读取。
- `image_processing_task`：处理项、状态、尝试次数、下一次执行时间、租约/超时、错误类别与版本栅栏。任务以“文档版本 + 图片出现 + 处理项”幂等。

活动图片向量的元数据至少包含 `record_type=image`、文档 ID、文档版本 ID、图片出现 ID、证据版本 ID、图片顺序和内容来源标记。检索与引用以证据版本 ID 定位，不能使用普通文本块的序号推测图片。模型生成的描述可参与回答，但回答上下文应注明“AI 生成的图片描述”；引文由服务端登记有效句柄，模型不能自行提供图片 URL。

聊天沿用现有 `<ref/>` 到 `<kb/>` 的确定性引用机制。点击图片引用后，服务端在权限检查后返回该证据版本的 OCR、描述、相邻正文和受保护的图片读取地址或图片内容；前端在引用弹层显示缩略图，可放大查看。当前前端 API 通过请求头发送令牌，图片展示可通过已鉴权的 Blob 请求或短时签名地址，不能直接暴露永久公开对象键。历史聊天固定到回答时的证据版本；重新分块后旧引用不指向新版内容。文档删除后撤销历史原图读取并清理副本；权限被撤销时也不得读取历史快照，旧聊天显示“来源已删除或无权访问”。

## 接口与配置影响

- 解析器输出需承载结构化图片出现，而不是只返回 `Text`；`DocumentProcessService` 必须把解析元数据和图片清单传至持久化及任务阶段。不能仅在 OCR 后丢弃 `ParseResult.Metadata`。
- 新增图片证据详情/图片读取接口，以及失败项列表、手动重试接口；均按当前知识库权限校验，不以对象键作为授权凭据。
- 模型适配器采用独立的多模态请求类型，不能把 `image_url` 字符串塞进现有纯文本 `ChatMessage.Content`。配置默认模型 ID 为 `Qwen/Qwen3.8-27B`，平台密钥只经安全配置注入。
- 发布阶段需处理活动版本、历史快照与向量的一致性；数据库事务不能覆盖外部对象存储调用，须记录待清理对象并执行幂等补偿。图片删除必须覆盖当前副本、历史快照与失败任务产生的临时副本。

## 验收场景

1. 混合 PDF 中正文、扫描文字、图表分别可检索；图表引用弹层只显示对应一张原图，描述与 OCR 明确分栏。
2. OCR `no_text` 且描述 `described` 的照片可检索；OCR `success` 且描述 `error` 的图片可按 OCR 检索，文档最终为 `partial`；两项正常无内容的空白图片不制造检索文本。
3. 图片专属文件在两项均无内容或均失败、且无其他可检索内容时为 `failed`；有正文但一图失败时为 `partial`，正文立即可检索。
4. 描述尚在运行时，已发布正文和 OCR 可检索，界面显示处理中；重试失败不清除上一可检索版本。自动重试耗尽后可手动仅重试失败项。
5. DocReader 故障且 Tika 提取到文本时为 `partial` 并标记图片清单未知；DocReader 恢复后重新确认图片并收口。
6. 同图在两个位置出现时产生两个出现 ID、独立引用；图片很多或单图过大时不静默跳过，也不因超限直接丢弃整份已提取内容。
7. 旧图片任务在文档刷新、重分块或删除后迟到，不能写入新活动版本；旧聊天引用仍展示原证据版本，删除或权限撤销后不可读取原图。
8. Markdown/HTML 外部链接图片不下载，文档状态与界面明确指出未处理；AI 图片描述不生成现有摘要或预测问题向量，原有 OCR 文档摘要能力不回退。
9. 真实联调使用硅基流动 `Qwen/Qwen3.8-27B` 发送带图请求，验证账号可用性、返回格式、超时/限流与用量记录。测试图至少包含文字扫描、图表、流程图、照片和空白图；人工检查描述只陈述可见内容。

## 实施前的代码差距

- `ParseResult` 只有文本与元数据，`extractDocumentText` 丢弃元数据；DocReader 当前直接调用 OCR 并把结果写回 Markdown。
- 现有文档状态没有 `partial`，chunk 日志只区分成功/失败；任务队列是进程内 goroutine，不能承担持久化图片重试。
- 当前文本块 ID 按序号生成、重分块时替换旧块；引用详情仅返回 chunk 文字，无法保持图片证据快照或展示原图。
- Tika 回退只取文本，尚不能标记图片清单未知；Markdown/HTML 外部图片没有明确的未处理状态。

以上为待实现差距，不表示这些行为已上线。
