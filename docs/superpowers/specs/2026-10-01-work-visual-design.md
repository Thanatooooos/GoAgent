# Work 界面与视觉设计

日期：2026-10-01。

状态：已确认首页、合并导航三分区、扩大文档区和中性灰白视觉已接入正式业务。真实浏览器、深色对比、键盘和移动导航验证见 [交付报告](../reports/2026-10-02-work-delivery-audit.md)。本文末尾原型段落保留开发前设计证据，不代替实际业务验收。

## 1. 总体方向

Work 是个人和 AI 持续完成工作的空间。界面以对话和正在处理的内容为中心，沿用现有聊天界面的中性、简洁风格：浅灰导航、白色内容区、细分隔线、克制的圆角，少量蓝色提示当前上下文及协作状态。

学习、技术选型和日常工作使用同一套主题界面，名称、描述和实际内容体现差异，不建立三个独立模板。创建主题仍只需名称与一句描述。

## 2. Work 首页

- 展示主题卡片，桌面两列，窄屏一列；显示名称、一句话描述、最近活动与可继续的对话。
- 页头保留“新建主题”，创建后直接进入空白对话；不强制填目标模板、期限或任务。
- 已归档主题单独分组，标明只读与恢复入口。
- 不显示强制截止日期、进度百分比或预设任务数量，日常工作主题可以持续存在。

## 3. 主题工作区：聊天优先

```text
合并的导航侧栏          当前对话                     可收起的专题面板
────────────────      ──────────────────          ─────────────────
应用入口：聊天 / Work   主题名称 / 对话名称           进展 | 文档 | 资料
返回全部主题            当前事项选择                 全部 / 当前事项
当前主题名称            对话消息                     目标与约束
+ 新对话                共同文档入口                 已确认决定
主题内对话列表          待确认的进展建议             待解问题
                        消息输入框                   下一步
```

已确认将应用导航与主题对话列表合并在一个侧栏中，减少同时展开的列数。实际应用入口沿用主导航，原型只突出聊天和 Work。

主题名与对话名同时可见，当前事项体现协作上下文；切换事项不创建新主题，进展可以看全部或当前事项。文档、资料与进展不串到其他主题。

在约 1024px 的桌面预览中，左侧栏约 184px，进展面板约 270px，中间聊天使用剩余宽度；较宽桌面可以适当增加侧栏与面板宽度，并限制消息阅读行宽。

右侧初次进入展示进展，之后记住用户的展开与收起选择。收起后在页头保留“专题”入口。进展使用分组文字与轻量列表，各组可为空；手动编辑后直接保存。

“文档”是独立工作成果在界面中的主要名称，资料是引用来源。上传 Word/PDF 第一版仍作为参考资料。

## 4. 共同文档：为正文腾出空间

打开共同文档后，保留原聊天上下文，右侧扩展为较宽编辑区，中间聊天适当收窄。

编辑区从上到下：标题与版本入口、当前修改方与保存状态、主要操作、简洁格式工具栏、富文本正文。正文使用安静的纸面容器，支持标题、段落、列表与简单表格。

| 状态 | 顶部表达 | 操作与行为 |
| --- | --- | --- |
| 人正在编辑 | 由你编辑 · 已保存 / 未保存 | 保存、交给 AI 修改 |
| 准备交接 | 本轮修改要求 | 保存并交给 AI、取消 |
| AI 正在修改 | AI 正在修改 · 本轮交给 AI | 同一正文暂不可手动编辑；未完成内容不成为保存版本 |
| AI 完成本轮 | 由你编辑 · 新版本已保存 | 变更摘要、查看修改、撤回本轮修改，允许继续写 |
| 保存失败 / 冲突 | 未保存 / 需要处理差异 | 保留本地输入，解决后再交接 |
| 主题归档 | 已归档 · 只读 | 查看与恢复，无编辑和交接操作 |

轮次与版本分别表达：人一轮可以保存多个版本，聊天并不自动交接文档。文档保存不会自动确认专题进展。

聊天输入区域显示“正在讨论：文档名称”。完成修改后在聊天返回摘要与文档入口；原型通过编辑区状态提示演示轮次回交，完整版本差异和冲突处理仍待实现。

## 5. 进展建议与资料

进展建议在聊天中使用轻量卡片，显示新增、修改、移除以及待确认状态，操作为确认、编辑、忽略。确认后更新右侧进展，确认前不显示为已确认事实。

常规 AI 消息保持无外框阅读区域。文档入口使用简洁文件行，进展面板不堆叠独立状态卡片。

资料面板使用文件、知识库和链接的列表，用文字明确处理中、可使用、失败或来源不可用；状态不只依赖颜色。资料添加、读取和文档转换沿用已确定的产品边界。

## 6. 视觉约定

| 元素 | 浅色建议 |
| --- | --- |
| 主背景 | 白色 `#FFFFFF` |
| 导航与轻背景 | 浅灰 `#F7F7F7` |
| 主要文字 | 深灰 `#2F2F2F` |
| 次要文字 | 灰色 `#707070` |
| 分隔线 | `#E8E8E8` |
| 选中与悬停 | 中性浅灰 `#EDEDED` |
| 少量上下文提示 | 蓝色 `#3164BC`，配浅蓝背景 |
| 主要操作 | 深灰按钮、白色文字 |

正文建议 14–16px，层级依靠字号、字重与间距，辅助状态保持可读。使用现有 Lucide 风格线性图标。

消息输入框使用较大圆角，文档和建议卡使用较小圆角，正文纸面接近矩形。区域依靠细分隔线区分，弹窗可使用轻阴影。动效以 150–200ms 的反馈为主，尊重减少动态效果的偏好。

深色模式保持同样层级与布局：深灰主背景、稍浅侧栏、浅色文字，单独配对按钮文字与底色。文字对比、键盘焦点和状态文字列为实现验收项。

## 7. 窄屏

正式产品中，导航可收起为抽屉，专题面板改为独立内容视图或抽屉。打开文档时优先提供正文与返回原对话的入口，手机不维持三列。

当前对话内原型为便于同时检查内容，在窄屏将聊天与专题面板上下排列。这是预览呈现，不代表最终手机导航和焦点行为已经实现。

## 8. 开发前历史原型与验证范围

原型展示首页、主题聊天与进展、共同文档编辑。可以打开与收起面板、编辑并确认进展建议、手动编辑正文、保存并交给 AI、等待示例修改回交并撤回。

原型使用示例主题与本地交互，AI 修改为固定示例，不连接模型、业务 API 或资料处理。未修改业务前后端，也未安装编辑器依赖；不能将预览当作实际持久化、权限、冲突处理或 runtime 装配证据。

临时浏览器检查覆盖 1024、736、360、320px 的布局、进展编辑确认、创建主题、面板收起恢复，以及交接前保存、AI 轮次只读、回交与撤回。脚本和截图位于 `tmp/work-interface-*`，仅作为本轮视觉检查证据。
